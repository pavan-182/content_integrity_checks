Normalization & feature extraction

Implemented
Trigger: a structured abstract record existsRuns as: sequential per abstract

Key subprocesses

  • Create normalized title, body and section views
  • Keep original text and character offsets for evidence
  • Extract typed entities: gene, drug, disease, miRNA, lncRNA, protein, pathway, cell line, assay, endpoint, database, population and treatment class
  • Store value, type, section, sentence, method and version
  • Build one reusable, versioned feature object
Output: reusable feature object: original + normalized + masked text, entities, context, signatures and versions.
New hereShared feature index becomes the single representation used by retrieval, comparison, classification, clustering, reporting and evaluation.
Why: improve comparability while preserving evidence.

Evidence scoring & section weighting

Implemented
Trigger: each detector branch emits a hitRuns as: parallel per detector result

Key subprocesses

  • Separate primary, supporting and contextual evidence
  • Weight Results / Conclusions above Methods and generic content
  • Reward exactness, copied-block strength, distinctive title formulas and strong masked-body templates
  • Do not raise confidence when exact and entity detectors merge the same evidence
  • Never let supporting or contextual signals create high confidence alone
Output: detector-level scored evidence.
Why: not every textual overlap is equally concerning.
Optional side-check after a pair is flagged
6

Legitimacy context check

Implemented routingEndpoint research disabled
Trigger: after a pair is flagged, especially medium/high concernRuns as: side enrichment; can run in parallel with Stage 5

Key subprocesses

  • Compare trial/protocol ID, registry/database, study period, sample size, population and treatment arms
  • Report shared-author count, overlap %, corresponding author, affiliations and apparently unrelated groups
  • Compare primary/secondary endpoints and explicit follow-up, subgroup, extension or companion wording
  • Route shared trial IDs as Possible companion analysis
  • Route shared authors/affiliations as Possible related work
  • Use context for routing; never erase exact full-abstract or Results evidence
Output: context label + adjustment note.
Why: companion analyses can legitimately share language.
7

Evidence merging & transparent pair classification

Implemented
Trigger: detector scores and context are availableRuns as: sequential per flagged pair

Key subprocesses

  • Merge evidence into one canonical A–B pair without confidence promotion for duplicated evidence
  • Apply reproducible rules across primary, supporting and contextual evidence
  • Classify as Possible template reuse, Possible companion analysis or Possible related work
  • Record the complete rule path, limitations and uncertainty
  • Keep related/companion evidence visible but separate from integrity-risk findings
Output: classified canonical pair with rule path and evidence tiers.
ImplementedThis product-facing class determines review routing and which pairs may create suspicious-family edges.
Why: reviewers need one consolidated item per pair.
8

Family / cluster building

Implemented
Trigger: pair-level findings are finalizedRuns as: batch / whole corpus aggregation

Key subprocesses

  • Allow only Possible template reuse pairs to create suspicious-family edges
  • Keep related and companion pairs visible but outside suspicious-family edges
  • Choose a representative and verify every member against it
  • Break weak transitive links and identify outliers
  • Validate dominant title/body templates, substitutions and supporting family signatures
Output: verified template families + remaining pairs.
Why: prevent weak chain effects and keep clusters tight.
Validated behaviorRelated and companion links remain reportable but cannot create suspicious families or increase integrity risk.

Sequential vs parallel execution

  • Stages 1 → 2 → 3 are sequential at batch level.
  • Stages 4A and 4B run for each candidate pair.
  • Stage 4C was evaluated offline and remains disabled.
  • Stage 5 scores each detector hit; Stage 6 can run as a side-check.
  • Stage 7 waits for 5 and 6, then classifies sequentially.
  • Stages 8 → 9 → 10 run after pair-level processing completes.
